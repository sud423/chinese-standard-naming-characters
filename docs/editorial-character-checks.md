# 把规范字校验接入编辑流程：机器结果与人工核对怎样配合

[文章目录](README.md) · 永嘉取名网开源文档

“每个字都在规范字表里”可以成为内容编辑的一条依据。要决定一段姓名解释是否准确、候选是否值得继续比较，还需要读音、字义、组合关系和使用场景。本仓库负责给出可追溯的字表结果，下面说明怎样把它放进更完整的核对过程。

## 先保留真正被检查的文字

编辑器或导入程序可能拿到带空格、异体选择符或补充平面字的文本。核对时保留原文，才能知道哪一个位置出现差异。如果产品允许整理输入，应显示整理前后内容，并在确认后检查最终版本。

下面用合成输入演示结果读取；这里的文字仅用于说明接口：

```python
from yongjia_naming import check_name

report = check_name("李 A").to_dict()
assert report["text"] == "李 A"
assert report["all_in_table"] is False
assert report["characters"][1]["codepoint"] == "U+0020"
assert report["characters"][1]["in_table"] is False

for item in report["characters"]:
    if item["in_table"]:
        record = item["record"]
        print(item["position"], item["codepoint"], record["source_ref"])
    else:
        print(item["position"], item["codepoint"], "未在 2013 版字表中匹配")
```

位置按 Unicode 码点从 1 开始计数，空格也占一个位置。界面如果使用不同的选择或光标单位，需要做对应转换，不能直接拿 JavaScript 的 UTF-16 码元偏移量代替。

## 分清“在表”“表外”与“没有完成校验”

| 实际情况 | 编辑界面怎样表达 | 下一步 |
| --- | --- | --- |
| 调用完成，全部字符匹配 | 所有码点均在 2013 版字表中匹配 | 继续读音、字义与使用核对 |
| 调用完成，部分字符未匹配 | 显示具体位置、原字与码点 | 核对准确文字、字表版本和用途 |
| 输入为空、数据读取失败或数据校验失败 | 本次校验未完成，并说明错误 | 修复输入或数据问题后重试 |

第三种情况是调用或数据错误，不能把没有返回结果理解成“没有发现问题”。本仓库的 API 以异常报告此类错误；命令行退出码 `0`、`1`、`2` 分别表示全部在表、存在表外字符、参数或执行错误。调用方需要按自己的界面与日志约定处理。

对于表外结果，先核对原始字符。字没有匹配到这份字表，不能直接推出它是错字，也不能直接作出姓名登记结论。字表级别同样不等于姓名评分。

## 把后续问题拆成可以回答的检查项

下面是供编辑使用的核对清单，属于方法建议；当前开源包只提供第一项的字表查询能力。

| 问题 | 需要的材料或动作 | 应留下的说明 |
| --- | --- | --- |
| 实际输入是什么，是否在表？ | 原文、码点、字表版本与查询记录 | 哪个字符匹配，哪个位置需要核对 |
| 连姓应该怎样读？ | 对应字义、姓氏读法资料，完整姓名试读 | 采用的读音，以及是否容易需要报字 |
| 解释采用哪个义项？ | 具体辞书条目与上下文 | 字典含义、组合解释和家庭心意各是什么 |
| 声称出自哪里？ | 作者、篇名、原句及必要上下文 | 是完整词语出处、单字取意，还是现代联想 |
| 放到生活里怎样使用？ | 正常语速叫读、听写、手写、常用设备显示 | 发生了什么具体问题，能否接受说明成本 |

例如“寓意好”还不够具体。解释应说清采用哪个义项、两个字怎样联系，以及这种联系来自已有词语还是家庭愿望。若正文只是把多个正面形容词并排写出，即使字表结果全部通过，也没有回答这些问题。

涉及古籍时，单字在某篇作品里出现，不等于完整名字出自该篇作品。涉及实际叫读时，声调标注也替代不了连姓试念。对材料不支持的部分，可以保留待核对项，再补充依据。

## 让修改与核验对应起来

正文改了用字、读音或出处后，应重新核对受影响的内容，并确认标题、正文、卡片和展示文字对应同一最终版本。仅修改排版则按实际影响检查，不需要把一次视觉调整写成新的用字结论。

对于多个候选，可以逐项记录“采用的含义、实际叫读、书写和使用成本”，帮助读者看清区别。没有明显优劣依据时，说明各自适用的偏好和取舍，比给出一个无法解释的总分更有帮助。
